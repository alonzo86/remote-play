# TV app flow

Status: **built**. Visual style: the 8-bit arcade style (FD-18), built in phase 1 of `docs/ARCADE_STYLE_PLAN.md` for the menus, the phone and the game shell. The game worlds are pixel worlds too (phases 2 to 4 are built, REQ-GM-47i to 47n). This file holds the decisions (FD-n)
and the requirements (REQ-FL-n) of the TV app flow. The logo image and the Android
splash image exist since 2026-10-10 (FD-21 (naming), REQ-FL-50, REQ-FL-51).
Style: ASD-STE100 Simplified Technical English, like the other requirements files.

## 1. Flow

```
OS splash ──> Logo screen ──> Connect controllers ──> Games ──> (Variant step) ──> Game
 (Android)     (in game)        QR, code, 4 slots      tiles      for example        │
                                      ▲                   │       marble tracks      │
                                      └──── Back ─────────┘◄──── Back / Menu ────────┘
                                      │
                                   Back: quit confirm
Settings: an OPTIONS button on the Games screen opens the Settings screen. The players badge opens the Players modal.
```

## 3. Requirements

### Splash and logo screen
- REQ-FL-50: Logo file: `assets/logo/logo.png`, PNG with a transparent background, 1600x600 px, the logo centered with at least 80 px of empty space on every side. It must read well on the black background (FD-18); pixel art fits the style. The logo screen shows it at 1200x450 px (62.5% of the screen width; the file has 4 px per logo pixel, so 3 screen pixels per logo pixel) with sharp pixels (nearest filter). The file is the mascot (a smiling blue phone with a yellow screen that sababis, white motion lines) and the word SABABI in the arcade font, yellow with a blue pixel shadow, the letters on a wave (FD-21). If the file is missing, the screen draws the text "SABABI" in the arcade font (96 px, yellow) with the line "PHONE MOTION CONTROLLER GAMES" under it.
- REQ-FL-51: The Android splash (REQ-FL-1) uses black `#000000` as the background color (`boot_splash/bg_color`). It shows `assets/logo/splash.png` (`boot_splash/image`, 432x432 px, transparent, the mascot of the logo, no filter). The mascot stays inside the middle circle of 288 px, so the round crop of Android 12 and later does not cut it.
- REQ-FL-1: The app sets the Android splash (background color and icon) in the project settings.
- REQ-FL-2: After the OS splash, the TV shows a logo screen with an animation. It lasts 2 to 3 seconds. At the first start it waits for the language choice instead (REQ-FL-60).
- REQ-FL-3: OK, or a tap on a touch screen, skips the logo screen. Back does not show it (FD-6). At the first start OK chooses the focused language and Back chooses it too (REQ-FL-60); a tap outside the two items does nothing.
- REQ-FL-4: The logo screen starts the network services (the server) while it shows, so the Connect screen is ready at once. The TV reads its LAN address each second and shows a new room code when the address changes (REQ-FL-84).

### Connect screen
- REQ-FL-5: The screen has two columns that start at the same top edge (the title is level with the top of the QR card) and sit in the middle of the screen. Left: the QR code on a white square in a double frame (REQ-FL-38), with the words "ROOM CODE" and the 4-letter room code below it. Right: the title "PLAYERS" (no player count; the slots show who joined), one line of help text, and 4 player slots (REQ-FL-8). The screen does not show the WebSocket address (FD-11).
- REQ-FL-6: The screen has no button (FD-17). A line at the bottom, centered, inside the safe area (60 px margins, RISKS D5), says "PRESS OK TO CONTINUE" (yellow, 40 px, blinking, REQ-FL-42) as soon as at least one phone has joined. Before that the line is empty, except when the TV has no network address: then it says so in `UiTheme.BAD`, without blinking. The slot list shows who has joined.
- REQ-FL-7: OK opens the Games screen when at least one phone has joined. OK does nothing before that, and nothing while the quit question is open (REQ-FL-10).
- REQ-FL-8: A phone that joins or leaves updates the slots at once. A slot is a row (no box): a square (24 px) in the slot color, "1P" to "4P", the player name in upper case, and the state word at the right: "READY" in `OK`, "LOST" in `BAD`, "WAIT" in `TEXT_DIM`. An empty slot shows a dark gray square (`SLOT_EMPTY`) and no name. The state is always a word. A phone that leaves shows "LOST" for at most 5 s (`Protocol.SLOT_GRACE_MS`), then its slot is empty again (issue #44); a phone that returns with its token in that time gets the slot back. In a game the pause card of REQ-GM-30 is the status.
- REQ-FL-9: A phone that is already joined stays joined when the host goes Back from the Games screen to this screen.
- REQ-FL-10: Back on this screen opens a quit confirmation (Quit, Stay). The default focus is "Stay".

### Players modal
- REQ-FL-32: The modal shows the 4 slots with color and state, a QR code with the room code for new phones, and a Close button. It opens on the Games screen (FD-12).

### Visual style (8-bit arcade, FD-18)

These requirements replaced the Party Pop ones (FD-13) in phase 1 of `docs/ARCADE_STYLE_PLAN.md`, which has the reasons and the mockups. Sizes are for 1920x1080.

- REQ-FL-37: All screens use one palette, kept in `UiTheme` (`scripts/ui/ui_theme.gd`): `BG` black `#000000`, `TEXT` `#fcfcfc`, `TEXT_DIM` `#7c7c7c`, `ACCENT` yellow `#f8b800`, `FRAME` blue `#0058f8` (a line, never text), `OK` green `#00b800`, `BAD` red `#f83800`, `DISABLED` (= `TEXT_DIM`), `SLOT_EMPTY` `#3c3c3c`, and the confetti colors `ACCENT`, `OK` and `FRAME`. Every text color has a contrast of 4.5:1 or more on black (a test checks it). The player colors stay as they are in `Protocol`: a square next to the slot number, never the only cue. A few old names (`OUTLINE`, `CARD`, `CARD_TEXT`, `BG_DARK`, ...) point to these colors, for the games until their restyle.
- REQ-FL-38: There are no round corners, no shadows and no outlines around buttons. A panel (the QR card, a modal, a menu card) is black with a double frame: a 6 px `TEXT` line outside, 6 px of black, and a 6 px `FRAME` line inside (`UiTheme.frame()`, drawn by `arcade_frame.gd`). A box (a tile, a header box) has one 6 px line (`UiTheme.line_box()`): `TEXT_DIM`, and `ACCENT` with the focus. A button (the badge, OPTIONS, a phone button) is white, see REQ-FL-38a.
- REQ-FL-38a: Every enabled button on the phone and on the TV is white (issue #173, owner 2026-10-29). A boxed button (`UiKit.box_button()`, OPTIONS, the players badge, the swing card OK, the A and B buttons, RECENTER, DISCONNECT) has a white face (`UiTheme.BUTTON_FACE`, the `TEXT` token), a white 6 px edge and black text (`UiTheme.BUTTON_TEXT`, 20.5:1). The text color is black because white text on a white face cannot be read. A button has no color of its own: OK/BAD (SAVE, DELETE, IN, OUT, A, B), ACCENT (+, the pencil) and TEXT_DIM (BACK, EDIT, SHARE, ABOUT) are gone from enabled buttons; the pencil icon is black. Pressed is the reverse: a black face, white text and a white edge. A disabled button keeps its dim look (a `TEXT_DIM` line on black, dim text). A mark is a 12 px `ACCENT` border around the white face (`UiTheme.MARK_W`): the chosen answer of IN or OUT (REQ-GM-102) and the active player in the lists. The mark is a thicker line and a color, never the color alone, and it is symmetric, so it is the same in Hebrew. The focus (the TV remote on OPTIONS and the badge, a keyboard on a desktop run) is different on purpose: a yellow face (`ACCENT`) with black text (11.8:1) and the same 12 px border, so a focused button is never taken for a marked one; the yellow border of a mark is read against the black screen (11.8:1) and its thickness, not against the white face (1.9:1). A button has the same content margins in every state, so a focus or a mark never moves the layout. DELETE and QUIT are white like SAVE and STAY by the owner's wording (issue #173); DELETE is armed by a timer and QUIT asks first. A text menu item (REQ-FL-41) has no face: it is white text, the focus is the yellow (or red) text with the pixel cursor. A game tile is a picture with a frame, not a button. The look comes from `UiTheme.button_box()` and `style_button()` only. Tests: `tests/design_tokens.gd` (every enabled button type is white, black text, the focus mark and the disabled look; no screen styles a button by itself), `tests/ui_states_a.gd`, `tests/auto_r3_phone.gd`. Device: tests 16 and 17 (white on the sofa, Hebrew).
- REQ-FL-39: One font: Press Start 2P (SIL OFL), a TTF file in `assets/fonts/` with its license file. Every export preset packs the two `OFL-*.txt` files, so the license text travels with the app (a test checks the presets). The project font Sababi Pixel Hebrew is its fallback, for Hebrew player names. Both fonts are imported with antialiasing off, no hinting and no subpixel positioning (a test checks the import files), and every text size is a multiple of 8, so the pixels stay sharp. All UI text is upper case, also player names; the code does it where it sets a text (`to_upper()`).
- REQ-FL-40: Text on the TV is at least 32 px high at 1080p, also help text (read from a sofa).
