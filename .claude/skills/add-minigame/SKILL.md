name: add-minigame
description: Add a new minigame to the Sababi TV app. Use when asked to create a game, mode or level type.
---

0. The game is also for children (REQ-GM-80 to 84): friendly made-up characters, no violence against anything alive, no blood and no scary things (toy beams at lifeless things are fine); a mistake takes no points away, and a player who is out keeps the points and waits only briefly or as long as the others play in a team game; one hint line; large and slow at the start; positive texts. Plan the game with that rule, and say in the requirements file how it is met.
   Agents: `product-engineer` writes the requirements and `ui-ux-designer` makes the mock and the tile (the user approves the look first); `software-architect` is asked only when the game needs a change across modules or the protocol; `sw-developer` builds; `automation-developer` and `qa` write the tests and the manual steps; `localization-reviewer` lists the strings (see "Agents and workflows" in `CLAUDE.md`).
   Write the requirements first. Copy `docs/games/TEMPLATE.md` to `docs/games/<id>.md` and fill it in. Read `docs/GAME_REQUIREMENTS.md`:
   the general requirements (all games, plus 2D or 3D) apply, and the game file lists its gaps and its own `REQ-<XX>-n` requirements.
   Show the file to the user before you write code if a requirement is a design choice.
1. Create `scripts/game/<name>/<name>_game.gd` that `extends "res://scripts/game/minigame.gd"`. Look at `maze/maze_game.gd` and
   `marble_race/marble_race.gd` (3D) for the style.
2. Override `_game_ready()`, `_game_tick(delta)` and `_game_draw()`. Read input only through `player(slot)`:
   `tilt()`, `pointer()`, `is_down()`, `button_pressed`, and the raw values. Never import anything from `scripts/net/`.
   Use `participants` for the players, `is_paused()` to freeze logic, and `App.server.haptic(slot, ms)` for feedback (`Haptics.pulse()` in `scripts/game/haptics.gd` adds a cool-down for each slot).
   Use `RoundClock` (`scripts/game/round_clock.gd`) for the 3 s countdown and the playing time. Do not bind A or B to recenter: the RECENTER button does it (REQ-GM-37). List the controls of the pad in the `pad` field of the registry entry (`a`, `b`, `recenter`; REQ-GM-37a): the pad shows only those. A game played with swings of the phone sets `"swing": true` there too (REQ-GM-102).
3. Add one entry for it in `scripts/game/registry.gd`, with the `doc`, `description` and `tile` fields. The Games screen is built from the registry. For a 3D game, extend `minigame_3d.gd`.
4. Follow the visual language (REQ-GM-45 to 49): use the shell (`scripts/game/shell.gd`, `open_menu`) for titles, the leader chip (`draw_leader_chip()`, with `_scoreboard()`; REQ-GM-46) and the name tags of the countdown (`draw_name_tags()`; REQ-GM-46a), the timer pill, hints (on a dark plate), countdown and menus,
   the slot color for everything of a player (and nothing else: no number and no avatar on a ball, marble or cursor, REQ-GM-46; the name is on the chips and the countdown tags), and the toy-like world rules (rounded shapes, flat saturated colors, dark outline on key objects;
   in 3D use `add_outlined_mesh`). Keep text inside the 60 px TV safe margin, and all text at 28 px or more. A key object is at least 48 px high on screen (REQ-GM-47e). The base class handles the players that leave: remove the objects of a slot in `_on_player_left(slot)` (REQ-GM-21), and it shows the "No players connected" menu when nobody is left (REQ-GM-22, 30a). Set `is_over = true` when you open the result menu. Draw the chips with `Shell.player_chips()` and a 2D ball with `Shell.ball()`. For a score, keep a `Scoreboard` and end the round with `open_results(board, tiers)` (REQ-GM-70 to 73; it also takes extra buttons and a score formatter, and a player without a score goes in with `set_unfinished()`): a timed round uses `RoundClock.new(3.0, duration)`, and a game for one player lists its medal tiers in its requirements file. A 2D game draws its world in the low-resolution pixel view (REQ-GM-47i to 47n): return true from `_pixel_world()`, draw the world in `_world_draw(ci)` with `Shell.pixel_ball()` and `Shell.snap()`, and the slot numbers and any text in `_game_draw()` (see `sumo_bumpers_game.gd`). Pick the background from the arcade set (REQ-GM-48). A 3D game is drawn in the pixel view by `minigame_3d.gd`: use `world_to_hud()` for HUD positions and `Shell.ball_number()` for slot numbers. The UI is English and Hebrew (REQ-GM-47o): every text is a key of `assets/lang/strings.csv` (a row with the key, the English and the Hebrew text; never English text in the code) and goes through `Lang.t()`, and a text with a name or a number is a format key for `Lang.f()` (never joined pieces); add a row for every new title, description, setting name and hint (`tests/smoke_lang.gd` fails without it); put your own HUD text with `Shell.mx()` so that it mirrors in Hebrew. 
   Make the tile screenshot with `tools/make_tiles.gd` and check it next to the Games screen (REQ-GM-49).
4a. Decide the personal best (REQ-GM-98): override `best_key()` (a key that is also added at the end of `ProfileKeys`, with its direction) and `best_value()` when the saved number is not the score, or leave the key empty and write the exception row in the requirements file (`docs/games/TEMPLATE.md`). Add the game to `tests/smoke_bests.gd`.
5. Add a check to `tests/smoke_tv.gd` (start the game with simulated phones, check one state change), and unit tests for pure logic.
   Put the requirement ID in the check text. Add a test to `docs/MANUAL_TESTS.md` for what only a device can check: the steps, a results table with "Evidence to capture" and a row in its Summary. Add the test to the list in `CLAUDE.md` (Manual tests).
   Every script of the game needs 80% line coverage (`tools/coverage.sh`, REQ-GM-63). Test the rules of the game (win, collision, leaving
   players, buttons), not only that it starts.
6. Run the `run-tests` skill and the `review` skill (the `code-reviewer` agent runs it), then update the README project structure if needed.
   Set the status of each requirement (Done, Open, Device) so that the file matches the code.
